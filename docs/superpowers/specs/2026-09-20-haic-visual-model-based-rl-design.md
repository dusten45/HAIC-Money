# HAIC 시각 강화학습 및 행동 탐색 설계

- 작성일: 2026-09-20
- 상태: 검토 요청
- 대상: 2026 HAIC CarRacing AI Challenge, `variables-6`

## 목표

픽셀 관측으로 주행하는 강화학습 에이전트를 만들고, 각 `act()` 호출의 계산 시간을 활용해 다음 행동을 탐색한다. 주행 결정의 주체는 학습된 정책으로 둔다. 규칙 기반 제어는 모델 출력이 유효하지 않거나 계획 계산이 끝나지 않은 경우에 한해 안전한 행동을 반환하는 보조 장치로 제한한다.

공식 우선순위는 완주자가 미완주자보다 앞서고, 완주자끼리는 시뮬레이션 랩타임이 짧은 순이다. 따라서 학습 중 누적 보상만으로 모델을 고르지 않고, 검증 시 완주율을 먼저 높인 뒤 랩타임을 낮춘다.

## 입력과 제약

- `Agent.reset()`과 `Agent.act()`는 `(4, 84, 84)` 크기의 최근 흑백 프레임 스택을 받는다.
- `act()`는 `[steer, gas, brake]` 세 값을 반환한다. 트랙 지도, 트랙 ID, 시드, 차량의 원시 물리 상태는 별도 인자로 주어지지 않는다.
- 렌더된 계기판에는 속도와 회전 관련 신호가 있지만, 관측 전처리 과정에서 이미지가 축소되고 회색조로 변환된다. 학습은 계기판과 주행 장면을 함께 처리하고, 계기판 수치 추정은 시뮬레이터 상태를 보조 정답으로 사용하는 보조 학습 목표로 둔다.
- 공식 안내의 기본 시간 제한은 `Agent` 초기화 10초, `reset()` 호출 5초, `act()` 호출 5초이며, 메모리 제한은 1,024 MB다. 기본 로컬 설정은 한 행동을 4개 원본 프레임 동안 유지한다.
- 평가 때는 Python 3.11/Linux CPU 환경에서 인터넷 없이 실행해야 한다. 정책과 계획 모델은 ZIP 안에 포함하고 CPU 추론으로 동작시킨다.
- 충돌 손상과 오프트랙 종료가 점수에 직접 영향을 준다. 다섯 번째 장애물 충돌은 리타이어 조건이므로 계획 모델은 충돌 위험을 강하게 반영한다.

## 설계

### 1. 시뮬레이터 기반 학습

로컬 `variables-6` 시뮬레이터에서 여러 `track_id`와 시드로 에피소드를 수집한다. 학습·튜닝에 사용하지 않을 검증 시드 묶음을 따로 보관한다. 에이전트가 입력받는 영상·프레임 스킵·손상 규칙은 평가와 일치시킨다.

### 2. 학습된 시각 정책

작은 CNN이 프레임 스택을 인코딩하고 PPO actor-critic이 연속 조향·가속·제동 분포를 출력한다. 보조 출력은 속도, 회전, 다음 시점의 잠재 표현, 도로 진행 및 위험 신호를 추정한다. 시뮬레이터의 실제 상태는 학습용 보조 레이블과 보상 계산에만 사용하며, 제출 정책의 추론 입력으로 사용하지 않는다.

### 3. 학습된 짧은 미래 예측 모델

정책의 잠재 상태와 후보 행동을 받아 다음 잠재 상태, 진행량, 충돌·오프트랙 위험을 예측하는 작은 앙상블 모델을 학습한다. 여러 모델의 예측 차이는 불확실성으로 계산해, 예측이 불안정한 후보에 위험 비용을 더한다. 잠재 예측 모델은 실제 CarRacing 환경을 `act()` 안에서 실행하지 않는다.

### 4. 호출마다 실행하는 제한시간 계획

각 `act()` 호출에서 정책이 행동 후보의 초기 분포를 제안한다. CEM 방식으로 행동 시퀀스를 반복 개선하며, 예측 진행량과 시간 비용, 충돌·이탈 위험을 함께 평가한다. 이전 호출의 계획을 한 칸 이동해 초기 후보로 재사용한다. 최고 계획의 첫 행동만 반환하고, 새 프레임을 받으면 다시 계획한다.

탐색기는 호출 제한 직전에 멈추는 anytime 구조로 구현한다. 최대 계획 예산은 4.5초로 두어 5초 제한에 여유를 남긴다. 계획이 수렴하면 더 일찍 반환하고, 제한 시간에 가까워지면 가장 좋은 유효 계획을 반환한다. 정책의 즉시 행동은 항상 유효한 fallback으로 유지한다. 기본 실행 모드는 가능한 한 호출별 예산을 활용하되, 전체 에피소드 실제 실행 시간도 함께 측정한다.

### 5. 규칙 기반 로직의 범위

규칙 기반 코드는 정상 주행 행동을 정하는 주 제어기로 사용하지 않는다. 유한성·범위 검사, 계획기 제한시간 관리, 계획 실패 시 정책 행동 반환, 비상 시 저속·무동작 fallback에만 사용한다. 도로 추종·속도 결정·장애물 회피는 강화학습 정책과 학습된 미래 예측 점수의 책임으로 둔다.

## 보상과 모델 선택

학습 보상은 전진 진행과 완주를 높이고, 시간 경과·장애물 충돌·연속 오프트랙을 낮추도록 구성한다. 가능한 경우 공식 종료 조건과 같은 완주·진행 신호를 사용한다. 체크포인트 선택은 다음 순서로 한다.

1. 검증 시드 완주율
2. 완주 에피소드의 중앙값 및 90백분위 랩타임
3. 미완주 에피소드 진행률과 리타이어 사유
4. 충돌 수, 예측 모델 오차, `act()` 실행시간

최종 비교에는 PPO 정책만 사용하는 경우와 정책에 제한시간 계획기를 추가한 경우를 모두 포함한다. 계획기가 보류 검증 시드의 완주율·랩타임을 개선하지 않거나 제한시간을 넘기면 계획기 설정을 낮추거나 사용하지 않는다.

## 검증 계획

- Python 3.11 가상환경에서 시뮬레이터 의존성을 준비하고, 먼저 기본 환경의 폐쇄루프 주행이 가능한지 확인한다.
- HUD 보조 추정이 84×84 흑백 입력에서 유효한지, 프레임 스택과 함께 측정한다. 계기판 신호가 손실되어도 전체 정책은 원본 픽셀로 주행할 수 있어야 한다.
- 정책 학습은 여러 트랙·시드로 수행하고, 검증 전용 시드에서 완주율과 랩타임을 평가한다.
- 정책 단독과 정책+계획기의 성능을 같은 검증 에피소드에서 비교한다.
- CPU 평가 경로에서 초기화·호출 시간, 메모리, 유효 행동 반환 여부, 전체 에피소드 실제 시간을 기록한다.
- 공식 평가에서 금지된 import와 인터넷 접근 없이 실행되는 제출 구성을 확인한다.

## 위험과 대응

- **HUD 신호 축소 손실:** HUD를 단일 센서로 가정하지 않는다. CNN이 전체 이미지를 계속 사용하고, HUD 추정은 보조 특성으로 결합한다.
- **잠재 예측 오차:** 짧은 계획 구간과 앙상블 불확실성 비용을 사용한다. 충돌·손상 직후에는 불확실성이 커질 수 있어 계획 행동을 보수적으로 평가한다.
- **계산시간과 에피소드 시간:** 5초는 호출별 상한이다. 호출마다 긴 탐색을 하면 전체 평가가 길어질 수 있으므로 전체 실행시간을 함께 측정한다.
- **로컬 Box2D 설치:** 현재 저장소의 고정 `box2d-py` 의존성은 이 Windows 환경에서 SWIG 빌드 단계에서 실패했다. 개발 가상환경은 호환되는 Windows 바이너리로 시뮬레이터 구동을 먼저 검증하되, 제출용 의존성은 Linux 평가 환경의 공식 고정 버전과 별도로 유지한다.
- **학습 비용:** 저장소에는 기존 학습 스크립트나 체크포인트가 없다. 먼저 작고 측정 가능한 PPO·예측 모델 기준선을 만든 뒤, 개선이 검증된 구성만 확장한다.

## 이번 설계 범위 밖

- 에이전트가 평가 시 트랙 ID·시드·전체 지도를 직접 읽는 기능
- 규칙 기반 주행기가 정상 행동의 주체가 되는 구성
- 평가 중 인터넷 다운로드 또는 평가 환경의 실제 시뮬레이터 상태에 접근하는 방식
- 검증 개선 없이 큰 모델·장시간 CEM 탐색을 추가하는 것
