# 자체 트랙 및 실행 로그 생성기 설계

## 1. 목표

기존 seed 기반 공식 맵과 별개로, 참가자가 직접 만든 새로운 도로 형상의 트랙을
생성하고 실제 로컬 물리 환경에서 주행해 `run.json`을 만드는 시스템을 추가한다.

최종 사용 흐름은 다음과 같다.

```text
트랙 자동 생성 또는 직접 수정
        ↓
map.json 저장
        ↓
로컬 실행기에서 Agent·수동·기본 정책 주행
        ↓
run.json 저장
        ↓
브라우저 재생·비교·분석
```

이 시스템은 공식 대회 평가를 대체하지 않는다. 공식 트랙은 기존 공식 환경으로
검증하고, 자체 트랙은 과적합 방지와 에이전트의 일반화 성능을 확인하는 별도 검증
세트로 표시한다.

## 2. 핵심 결정

### 공식 맵과 자체 맵을 분리한다

현재 `seed`는 공식 CarRacing 도로 생성 방식을 바꾸고, `track_id`는 공식 장애물
배치의 결정성에 관여한다. 숫자 `track_id=3`을 추가하는 것만으로는 새로운 도로
디자인이 만들어지지 않는다.

따라서 다음 두 종류를 명시적으로 분리한다.

- `official`: 기존 `track_id`와 `seed`를 사용하는 공식 환경 맵
- `custom`: 중심선, 도로 폭, 출발 방향, 장애물을 직접 저장하는 자체 맵

자체 맵은 `custom-track-0001`처럼 문자열 `map_id`를 사용한다. 기존 공식
`track_id` 필드는 공식 맵에서만 유지해 기존 `map.json`과의 호환성을 보장한다.

### 로컬 우선 실행

Box2D 물리와 Agent 추론은 로컬에서 실행한다. 서버는 맵 생성·맵 목록·로그 업로드와
같은 가벼운 기능만 담당한다. 이렇게 하면 공개 서버에서 매 스텝 물리를 실행하지 않아
CPU 부담과 실행 세션 관리가 줄어든다.

### 공식 물리 코드는 변경하지 않는다

기존 `core/`, `env_wrapper.py`, `damage.py`는 공식 평가와의 일치를 위해 수정하지
않는다. 자체 트랙은 별도 백엔드로 구현하고, 공통 실행기와 공통 로그 계약을 통해
공식 백엔드와 연결한다.

## 3. 범위

### 포함

- seed와 별개인 자체 트랙 데이터 모델
- 자동 트랙 생성기와 결정적 design seed
- 브라우저에서 자체 트랙 중심선과 도로 폭을 수정하는 편집 흐름
- 자체 트랙의 유효성 검사와 장애물 배치
- 공식 맵과 자체 맵을 모두 실행하는 공통 실행기
- baseline, `agent.py`, 브라우저 수동 조작 정책
- 실행 결과를 `run.json`으로 저장하는 로컬 API와 CLI
- 실행 직후 브라우저에서 로그를 자동 로드하는 흐름
- 기존 로그 재생·일시정지·스텝 이동·비교 기능과의 통합
- 서버의 맵 생성·목록·로그 업로드 API
- `D:\HAIC\maps`, `D:\HAIC\runs` 우선 저장

### 제외

- 자체 트랙을 대회 공식 평가 서버에 제출하는 기능
- 서버에서 Agent 코드나 Box2D 주행을 실행하는 기능
- 공식 대회 트랙의 물리 파일 수정
- 다중 사용자 계정, 협업 편집, 온라인 실시간 대전
- 프레임을 기본값으로 포함하는 대용량 로그 저장

## 4. 데이터 모델

### 4.1 맵 공통 필드

모든 맵은 다음 필드를 공유한다.

```json
{
  "schema_version": 2,
  "map_id": "custom-track-0001",
  "map_kind": "custom",
  "max_steps": 2000,
  "frame_skip": 4,
  "obstacle_mode": "custom_only",
  "obstacles": []
}
```

기존 schema 1의 공식 맵은 읽을 때 `map_kind: "official"`과 안정적인 `map_id`를
추론해 schema 2 내부 형태로 변환한다. 다시 내보낼 때는 새 형식으로 저장한다.

### 4.2 공식 맵

공식 맵에는 기존 필드를 유지한다.

```json
{
  "map_id": "official-track-1-seed-42",
  "map_kind": "official",
  "track_id": 1,
  "seed": 42,
  "obstacle_mode": "official_plus_custom",
  "obstacles": []
}
```

### 4.3 자체 맵

자체 맵은 미터 단위의 월드 좌표로 닫힌 중심선을 저장한다. 브라우저의 화면 크기와
관계없이 같은 물리 입력을 재현하기 위해 화면 픽셀을 저장하지 않는다.

다음은 필드 구조를 보여주는 축약 예시이며, 실제 생성 결과에는 유효성 검사를 통과한
더 많은 중심선 점이 저장된다.

```json
{
  "map_id": "custom-track-0001",
  "map_kind": "custom",
  "generator": {
    "template": "hairpin",
    "design_seed": 90421
  },
  "geometry": {
    "centerline": [[0.0, 0.0], [12.0, 3.5], [18.0, 14.0]],
    "width": 8.0,
    "start_index": 0,
    "direction": 1
  },
  "obstacle_mode": "custom_only",
  "obstacles": [
    {"progress": 0.42, "lateral": -0.25, "radius": 1.2}
  ],
  "max_steps": 2000,
  "frame_skip": 4
}
```

중심선은 최소 점 개수, 중복점, 급격한 곡률, 자기 교차, 도로 폭 대비 좁은 구간,
출발선 주변의 장애물을 검사한다. 검사에 실패한 맵은 저장·실행하지 않고 브라우저에
수정 가능한 이유를 표시한다.

### 4.4 실행 로그

실행 로그는 공식·자체 맵을 모두 표현할 수 있도록 맵 참조와 환경 종류를 포함한다.

```json
{
  "schema_version": 2,
  "run": {
    "run_id": "run-20260918-0001",
    "created_at": "2026-09-18T12:00:00Z",
    "map_ref": {
      "map_id": "custom-track-0001",
      "map_kind": "custom",
      "fingerprint": "..."
    },
    "environment": "custom-v1",
    "policy": {"kind": "agent", "name": "submission-agent"}
  },
  "track": {"points": [], "width": 8.0},
  "steps": [],
  "summary": {}
}
```

기존 schema 1 로그는 계속 읽을 수 있어야 한다. 기본 로그는 상태와 궤적만 포함하고,
카메라 프레임은 사용자가 선택한 경우에만 추가한다.

## 5. 트랙 생성과 편집

### 자동 생성

첫 버전의 생성 템플릿은 `oval`, `s_curve`, `hairpin`, `chicane`으로 제한한다.
각 템플릿은 design seed를 받아 같은 입력에서 같은 중심선을 만들며, 생성 후 공통
유효성 검사를 통과해야 한다. 배치 생성은 seed 범위를 받아 여러 자체 맵을 만들고,
각 결과에 고유한 `map_id`를 부여한다.

### 브라우저 편집

맵 제작 화면에는 다음 기능을 둔다.

- 공식 맵과 자체 맵을 구분하는 배지
- 템플릿과 design seed 입력
- 자동 생성 및 여러 맵 생성
- 중심선 제어점 추가·이동·삭제
- 도로 폭 조절
- 시작점과 주행 방향 표시
- 장애물 추가·삭제·랜덤 배치
- 유효성 오류와 경고 표시
- 맵 JSON 저장·불러오기

미니맵은 중심선, 도로 양쪽 경계, 출발선, 공식 장애물, 사용자 장애물을 서로 다른
색으로 표시한다. 자체 맵의 장애물 위치는 `progress/lateral/radius`와 월드 좌표를
함께 보여 디버깅할 수 있게 한다.

## 6. 실행 엔진

### 공통 인터페이스

실행기는 맵 종류에 따라 백엔드를 고르되, 정책과 로그 기록기는 공통으로 사용한다.

```text
MapSpec
  ├─ official → OfficialEnvironment
  └─ custom   → CustomTrackEnvironment

Environment.reset() / step(action) / render()
Policy.reset(observation) / act(observation)
RunRecorder.record(...) / finish(...)
```

`CustomTrackEnvironment`는 동일한 차량 행동값 `[steer, gas, brake]`과 관측값
`(4, 84, 84)` 계약을 제공한다. 자체 환경의 로그에는 `environment: custom-v1`을
기록해 공식 환경 결과와 혼동하지 않는다.

자체 환경은 기존 vendored Box2D 차량 동역학을 재사용할 수 있는 부분은 재사용하되,
도로 표면·경계·진행률·결승선 판정은 자체 중심선에서 계산한다. 이 구현은 공식
CarRacing 트랙의 내부 타일 생성 방식과 분리하며, 공식 맵 실행 결과에는 영향을 주지
않는다.

### 정책 모드

- `baseline`: 파이프라인 확인용 기본 주행
- `agent`: 저장소의 `agent.py`를 불러와 실제 `reset/act` 호출
- `manual`: 브라우저 입력을 행동값으로 변환해 한 스텝씩 실행

수동 모드는 로컬 실행 API가 세션별 환경 상태를 보관하고, 브라우저가 행동 요청을
보낸 뒤 갱신된 상태를 받는 방식으로 만든다. 종료 시점에 recorder가 하나의
`run.json`을 완성한다. 브라우저가 닫혀도 마지막 저장된 로그는 유지한다.

### CLI와 로컬 웹 API

기존 CLI는 계속 지원한다.

```text
python -m local_simulator.run --map D:\HAIC\maps\custom-track-0001.json --output D:\HAIC\runs\run.json
```

실행 화면을 위해 정적 사이트와 로컬 API를 함께 제공하는 실행 모드를 추가한다.

- `GET /api/health`
- `POST /api/maps/generate`
- `POST /api/maps/save`
- `POST /api/runs/agent`
- `POST /api/runs/start`
- `POST /api/runs/{run_id}/action`
- `POST /api/runs/{run_id}/finish`
- `GET /api/runs/{run_id}`

로컬 통합 서버는 `web_simulator`와 API를 같은 origin에서 제공해 CORS 설정 없이
사용하게 한다. 기존 정적 파일 서버는 로그 보기 전용 모드로 계속 사용할 수 있다.

## 7. 웹 사용자 흐름

사이트는 다음 세 화면 흐름으로 구성한다.

### 맵 제작

공식·자체 맵을 선택하고, 자동 생성 또는 직접 편집한 뒤 저장한다. 저장 위치는
기본적으로 `D:\HAIC\maps`이며, 브라우저만 사용하는 환경에서는 JSON 다운로드로
대체한다.

### 실행

맵을 선택하고 정책, 최대 스텝, 프레임 기록 여부를 정한 뒤 실행한다. Agent 모드와
기본 정책은 연속 실행하며, 수동 모드는 키보드 조작과 일시정지·한 스텝 진행을
지원한다. 실행 중에는 현재 행동, 진행률, 속도, 손상, 충돌을 표시한다.

실행 완료 시 결과를 `D:\HAIC\runs`에 저장하고 현재 로그 재생 화면으로 자동 전환한다.

### 로그 분석

기존 재생 기능을 그대로 활용해 궤적·프레임·요약을 표시한다. 실행 모드에서 생성된
로그와 파일로 불러온 로그를 같은 비교표에 넣을 수 있어야 한다.

## 8. 서버 경계와 배포

원격 서비스는 로컬 실행 엔진과 분리한다.

### 원격 API

- 맵을 design seed로 생성하거나 목록·상세 조회
- 맵 JSON 저장
- 로컬에서 생성한 `run.json` 업로드
- 상태 확인

원격 서버는 Agent import, 수동 세션, Box2D 매 스텝 실행 API를 제공하지 않는다.
JSON 파일 저장소를 우선 사용하며 맵 생성 배치와 로그 업로드에는 개수·크기 제한을
둔다. 쓰기 API는 서버 환경 변수의 토큰을 요구하고 토큰은 저장소에 넣지 않는다.

사용자가 지정한 도메인이 준비되기 전에는 원격 서비스가 내부 주소에서만 동작하도록
한다. `server.koi3125.com:3125`는 현재 SSH 접속 포트이므로 HTTP 서비스 포트로
사용하지 않는다. 애플리케이션은 별도의 내부 포트에 바인딩하고, 최종 HTTP 도메인이
정해진 뒤 기존 Caddy가 해당 도메인에서 내부 포트로 reverse proxy한다.

정적 사이트만 필요한 경우에는 ChatGPT Sites 또는 기존 정적 호스팅에 배포할 수
있지만, 실제 Agent·Box2D 실행은 사용자의 로컬 실행기를 사용한다.

## 9. 오류 처리와 안전성

- 공식 맵과 자체 맵의 실행 백엔드를 화면과 로그에 명시한다.
- 잘못된 중심선은 저장·실행 전에 차단하고 원인을 표시한다.
- 장애물은 도로 밖, 출발·결승 안전 구간, 다른 장애물과의 위험한 겹침을 검사한다.
- API 입력은 허용된 필드만 받고 seed, 점 개수, 장애물 수, 반지름, 최대 스텝을 제한한다.
- Agent의 잘못된 action은 기존 공식 계약대로 검증·클리핑한다.
- 로컬 API가 꺼져 있으면 사이트는 파일 불러오기·로그 재생 모드로 자동 전환한다.
- 실행 중 예외가 발생하면 현재까지의 로그를 `failed` 상태로 저장하고 원인을 요약한다.
- 원격 로그 업로드는 파일 크기와 JSON 구조를 먼저 검사하며, 서버 경로를 입력으로 받지 않는다.
- 프레임 기록은 기본 비활성화하고 큰 파일은 `D:\HAIC`에만 저장한다.

## 10. 테스트와 검증

### 데이터·생성기

- 같은 design seed가 같은 중심선과 fingerprint를 생성하는지 확인
- 다른 design seed가 유의미하게 다른 트랙을 생성하는지 확인
- 템플릿별 폐곡선·폭·시작 방향·자기 교차 검증
- 편집 후 저장·불러오기가 geometry를 보존하는지 확인
- schema 1 공식 맵 읽기 호환성과 schema 2 맵의 저장·불러오기 왕복 확인

### 실행기

- 공식 맵 실행 결과가 기존 테스트와 달라지지 않는지 확인
- 자체 맵이 공통 observation/action 계약을 지키는지 확인
- baseline, Agent, manual 모드가 모두 유효한 `run.json`을 만드는지 확인
- 같은 맵과 같은 결정적 정책의 결정성 확인
- 종료·충돌·손상·진행률·프레임 기록 확인

### 웹과 API

- 자체 트랙 생성·편집·검증·내보내기
- 실행 시작과 수동 action 전달
- 실행 완료 후 로그 자동 로드
- 재생·일시정지·스텝 이동·속도 변경
- 여러 로그 비교
- API 중단 시 파일 기반 보기 전용 모드 전환
- 원격 API의 schema 검사·파일 크기 제한·토큰 검사

기존 `python -m unittest discover -s tests -v`, JavaScript 문법 검사, 브라우저 수동
검증을 모두 통과해야 한다. 공식 물리 파일과 제출용 `agent.py`의 변경 여부도
검증한다.

## 11. 구현 순서

1. schema 2 공통 맵 모델과 schema 1 호환 reader 추가
2. 자체 트랙 생성기와 geometry validator 추가
3. 자체 맵 미리보기·편집·저장 UI 추가
4. 자체 환경 백엔드와 공통 실행기 연결
5. Agent·manual policy와 `run.json` 생성 API 연결
6. 실행 화면에서 결과 자동 재생·비교 연결
7. 전체 테스트 및 브라우저 검증
8. 로컬 버전 안정화 후 원격 맵·로그 서비스와 Caddy 배포 준비

원격 배포는 로컬에서 자체 트랙 생성과 `run.json` 생성이 검증된 뒤 별도 배포 단계로
진행한다. 따라서 서버 설정 문제 때문에 로컬 시뮬레이터 개발이 지연되지 않는다.

## 12. 완료 조건

- seed를 바꾸지 않아도 새로운 도로 디자인의 자체 트랙을 생성할 수 있다.
- 자체 트랙에 `custom-track-*` 식별자를 부여하고 공식 트랙과 구분할 수 있다.
- 브라우저에서 자동 생성 트랙을 보고 중심선·폭·장애물을 수정할 수 있다.
- 공식 맵과 자체 맵을 로컬에서 실행할 수 있다.
- Agent·수동·baseline 실행이 모두 `run.json`을 만든다.
- 실행 완료 후 웹에서 해당 로그가 자동 재생된다.
- 실행 로그를 저장·불러오기·비교할 수 있다.
- 서버는 맵 생성과 로그 업로드만 담당하고 무거운 주행은 로컬에서 수행한다.
- 공식 물리 파일과 기존 공식 실행 계약은 유지된다.
- 전체 테스트와 브라우저 검증이 통과한다.
