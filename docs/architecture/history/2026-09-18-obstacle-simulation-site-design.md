# 장애물 배치 및 주행 시뮬레이션 사이트 설계

## 1. 목표

대회 공식 물리 환경을 기준으로 다음을 수행하는 로컬 시뮬레이터와 로그 재생 웹 애플리케이션을 만든다.

- seed와 track ID로 절차적 트랙을 자동 생성한다.
- 공식 장애물 또는 사용자가 지정한 추가 장애물을 배치한다.
- 로컬 공식 환경에서 차량을 실행하고 주행 로그를 저장한다.
- 로그 파일을 웹사이트에 올려 차량 움직임을 재생·일시정지·한 스텝씩 확인한다.
- 진행률, 완주 여부, 랩타임, 손상도, 충돌, 종료 사유를 표시한다.
- 여러 실행 기록을 비교해 이후 에이전트 제작 단계의 평가 기준으로 사용한다.

첫 단계의 산출물은 맵 제작기, 공식 물리 기반 로컬 시뮬레이터, 로그 재생 사이트다. 에이전트 학습·모델 비교·자동 개선 루프는 같은 실행기에 정책만 연결하는 별도 단계로 추가한다.

## 2. 범위와 제약

### 포함

- 공식 `CarRacing` 및 `CarEnvironment`를 사용하는 로컬 정확 모드
- 공식 장애물 6개를 유지하는 모드
- 공식 장애물을 제거하고 사용자 장애물만 사용하는 모드
- 공식 장애물에 사용자 장애물을 추가하는 모드
- 트랙 진행률 기반 장애물 배치
- 자동 seed/장애물 조합 생성
- 로컬 실행 로그와 요약 기록 저장
- 로그 파일 업로드·재생·비교가 가능한 브라우저용 정적 사이트
- 이후 `Agent.act()`를 연결할 수 있는 정책 인터페이스

### 제외

- `agent.py` 최종 구현과 학습 파이프라인
- 공식 평가용 `core/`, `env_wrapper.py`, `damage.py`의 수정
- 브라우저에서 공식 Box2D 물리를 다시 구현하는 작업
- 실시간 서버 세션과 서버 측 매 스텝 물리 실행
- 인증, 사용자 계정, 다중 사용자 협업
- 사이트에 로그를 영구 저장하는 데이터베이스

공식 물리 파일은 그대로 유지한다. 사용자 장애물 기능은 별도 로컬 시뮬레이터 모듈에서 공식 환경의 장애물 생성 인터페이스를 호출해 추가한다.

## 3. 사용자 경험

### 맵 제작기

1. seed와 track ID를 입력하거나 자동 생성한다.
2. 공식 장애물만, 사용자 장애물만, 공식+사용자 장애물 중 하나를 선택한다.
3. 진행률·좌우 오프셋·반지름으로 장애물을 추가·삭제·랜덤 배치한다.
4. 미니맵에서 결과를 확인하고 `map.json`으로 내보낸다.

### 로컬 시뮬레이터

맵 파일을 로컬 실행기에 전달해 공식 물리로 주행한다. 첫 단계에서는 기본 정책으로 계속 가속하는 baseline을 제공하고, 이후 같은 실행기에 `Agent.act()` 또는 다른 정책을 연결한다. 실행 중에는 차량 위치, 행동, 충돌, 손상, 진행률, 렌더링 프레임을 로그에 기록한다.

### 로그 재생 사이트

1. `map.json` 또는 실행 로그 파일을 드래그 앤 드롭한다.
2. 트랙 미니맵에서 차량의 이동 경로와 장애물을 확인한다.
3. 카메라 프레임이 포함된 로그라면 실제 주행 화면도 재생한다.
4. 재생·일시정지·한 스텝·처음으로 이동·재생 속도 조절을 사용한다.
5. 여러 로그를 불러와 완주 여부, lapTimeMs, progress, 손상도와 종료 사유를 비교한다.

사이트는 로그를 브라우저에서 읽고 재생한다. 재생 중 서버에 매 스텝 요청을 보내지 않으며, 한 번 올린 파일은 브라우저 메모리 또는 사용자가 명시적으로 내보낸 결과로만 유지한다.

## 4. 시스템 구조

```text
map.json
   ↓
local_simulator/run.py
  ├─ CarRacing + TimeLimit
  ├─ CarEnvironment
  ├─ custom obstacle placement
  ├─ policy adapter
  └─ run.json / optional frames.webm
       ↓ drag-and-drop or file input
Static replay site
  ├─ map editor
  ├─ log parser
  ├─ trajectory/camera playback
  └─ run comparison
       ↓
official core/ and env_wrapper.py (read-only)
```

로컬 실행기는 Python에서 공식 환경을 직접 실행한다. 사이트는 정적 HTML/CSS/JavaScript로 구성해 ChatGPT Sites 같은 정적 배포 환경에 올릴 수 있도록 한다. 브라우저에서는 Box2D를 실행하지 않으며, 서버도 재생 중 물리를 다시 계산하지 않는다. 이 구조로 사이트 호스팅 부담과 공식 물리와의 불일치를 모두 줄인다.

## 5. 트랙 및 장애물 모델

### 맵 artifact

맵 제작기와 로컬 시뮬레이터 사이에는 버전이 있는 JSON 파일을 사용한다.

```json
{
  "schema_version": 1,
  "track_id": 1,
  "seed": 42,
  "obstacle_mode": "official_plus_custom",
  "obstacles": [
    {"progress": 0.42, "lateral": -0.25, "radius": 1.2}
  ],
  "max_steps": 2000,
  "frame_skip": 4
}
```

맵 파일은 물리 실행 결과가 아니라 재현 가능한 입력 설정이다. 따라서 같은 소스와 의존성 버전에서 같은 맵을 다시 실행할 수 있다.

### 트랙

- `seed`는 공식 환경의 트랙 형상 생성에 사용한다.
- `track_id`는 공식 장애물 배치의 결정성에 사용한다.
- 동일한 `(track_id, seed)`는 동일한 공식 트랙과 장애물을 재현해야 한다.
- 자동 생성기는 seed를 무작위로 선택하되, 학습·검증용 seed 목록을 분리할 수 있도록 입력 seed를 저장한다.

### 사용자 장애물

브라우저에서는 월드 좌표 대신 다음 구조로 지정한다.

```json
{
  "progress": 0.42,
  "lateral": -0.25,
  "radius": 1.2
}
```

`progress`로 track point를 선택하고 `lateral`을 도로의 접선 방향에 직교한 오프셋으로 변환한다. 반지름과 개수에는 맵 제작기와 로컬 실행기에서 상한을 둔다. 사용자 장애물은 공식 모드와 분리하며, 공식 장애물과 겹치는 경우 경고하거나 해당 배치를 거부한다.

사용자 장애물은 트랙 생성과 워밍업이 끝난 직후 추가한다. 그러면 공식 50 raw-frame 워밍업, 프레임 스킵, 손상 판정, 접촉 리스너는 그대로 유지하면서 사용자 장애물만 추가할 수 있다.

## 6. 로컬 실행기와 로그 계약

### 실행기 명령

첫 구현은 다음 형태의 CLI를 제공한다.

```text
python -m local_simulator.run --map map.json --output D:\HAIC\runs\run.json
```

실행기는 맵을 검증하고, 공식 환경을 생성하고, baseline 또는 지정된 policy adapter를 매 제어 스텝에 호출한다. 종료 시 요약과 스텝 로그를 하나의 JSON 파일로 저장한다.

### 로그 구조

```json
{
  "schema_version": 1,
  "run": {
    "run_id": "...",
    "created_at": "...",
    "map": {},
    "policy": "baseline",
    "control_hz": 12.5
  },
  "track": {
    "points": [[0.0, 0.0, 0.0, 0.0]],
    "width": 0.0
  },
  "steps": [
    {
      "step": 0,
      "sim_time_s": 0.08,
      "action": [0.0, 1.0, 0.0],
      "position": [0.0, 0.0],
      "angle": 0.0,
      "velocity": [0.0, 0.0],
      "progress": 0.0,
      "damage": 0.0,
      "collision": false,
      "terminated": false,
      "truncated": false
    }
  ],
  "summary": {}
}
```

카메라 화면 재생이 필요할 때만 별도 `frames.webm` 또는 압축 프레임 묶음을 추가한다. 기본 로그는 미니맵 궤적 재생만으로 동작해 파일 크기를 작게 유지한다.

### 로그 업로드

사이트는 파일 선택 또는 drag-and-drop으로 `map.json`, `run.json`, 선택적 프레임 파일을 읽는다. 업로드된 파일은 브라우저 안에서 파싱하며, 매 스텝마다 서버를 호출하지 않는다. 로그가 schema version을 지원하지 않으면 사용자에게 명확한 오류를 표시한다.

## 7. 기록 저장

각 종료된 실행은 `run.json` 내부의 `summary`와 `steps`로 저장한다. 실행기에서 여러 실행을 돌릴 때는 각 JSON을 `D:\HAIC\runs`에 보관하고, 필요하면 나중에 요약만 합쳐 비교한다.

```json
{
  "run_id": "...",
  "created_at": "...",
  "track_id": 1,
  "seed": 42,
  "obstacle_mode": "official_plus_custom",
  "obstacles": [],
  "finished": false,
  "lap_time_ms": null,
  "progress": 0.137809,
  "damage": 0.0,
  "collision_count": 0,
  "retire_reason": "off_track"
}
```

대용량 프레임·체크포인트·실험 산출물은 `D:\HAIC` 아래에 저장하고, 소스 저장소에는 요약 데이터와 작은 테스트 fixture만 둔다. 저장 위치는 CLI 인자로 바꿀 수 있으며, 기본값이 불가능한 환경에서는 프로젝트의 `data/`로 fallback한다. 사이트는 로그를 서버에 영구 저장하지 않고 사용자가 필요할 때 파일을 다시 선택하도록 한다.

## 8. 오류 및 안전 처리

- seed와 track ID 범위를 맵 제작기와 로컬 실행기에서 검증한다.
- progress, lateral, radius, 장애물 개수에 상한을 둔다.
- 잘못된 맵 파일은 로컬 실행 전에 즉시 거부한다.
- 로그 파일은 schema version과 필수 필드를 검사한 뒤 재생한다.
- 매 스텝 입력은 공식 runner와 동일하게 유한성·shape·범위를 검증하고 클리핑한다.
- 사용자 장애물이 트랙 밖 또는 시작·결승 안전 영역에 있으면 경고하거나 거부한다.
- 공식 모드와 사용자 지정 모드를 화면에 명시해 기록을 혼동하지 않도록 한다.
- 로그 재생 중 종료 상태에 도달하면 자동 재생을 멈춘다.

## 9. 테스트 전략

### 단위 테스트

- progress/lateral을 월드 좌표로 변환하는 결과
- 동일한 seed의 트랙 재현성
- 공식·사용자 장애물 모드별 장애물 개수
- 장애물 반지름·개수·범위 검증
- 사용자 장애물 충돌 시 damage와 collision count 반영
- 실행 종료 시 `run.json` 기록 저장

### 로컬 실행기 테스트

- 맵 파일 검증과 자동 생성
- 동일한 맵의 트랙 재현성
- baseline 실행 후 유효한 `run.json` 생성
- 사용자 장애물 충돌과 damage 반영
- `Agent.act()` adapter를 연결해도 동일한 로그 schema 생성

### 로그 재생 사이트 테스트

- 유효한 로그의 미니맵 궤적 재생
- 선택적 카메라 프레임 재생
- 잘못된 schema와 누락 필드의 오류 표시
- 여러 로그의 기록 비교

### 수동 브라우저 검증

- 페이지 로드
- 맵 생성 및 내보내기
- 장애물 추가 및 미니맵 표시
- 로그 drag-and-drop
- 재생 버튼으로 연속 재생
- 재생 속도 변경과 일시정지
- 한 스텝 진행과 처음으로 이동
- 종료 결과와 기록표 표시

기존 `python -m unittest discover -s tests -v`도 매 변경 후 실행한다.

## 10. 배포 경계

사이트는 정적 파일만으로 로그를 읽고 재생하므로 ChatGPT Sites 같은 정적 호스팅 환경에 배포하기 쉽다. 공식 Python/Box2D 실행은 로컬 시뮬레이터에서 수행하고, 배포 사이트에는 맵 파일과 로그 파일을 사용자가 올린다.

이 구조에서는 사이트 서버가 물리 계산이나 세션을 유지하지 않는다. 외부 공개 URL을 만들 수 있는 환경에서는 정적 사이트를 배포하고, 그렇지 않으면 같은 파일을 로컬 정적 서버에서 실행한다. 별도 Python API 호스팅은 첫 단계의 필수 조건이 아니다.

## 11. 완료 조건

- 맵 제작기에서 재현 가능한 `map.json`을 만들 수 있다.
- 로컬 실행기가 공식 물리로 맵을 실행하고 `run.json`을 생성한다.
- seed/track ID로 재현 가능한 트랙을 생성할 수 있다.
- 사용자 장애물을 추가·삭제·랜덤 생성할 수 있다.
- 로그를 사이트에 올리면 트랙 미니맵과 차량 궤적이 재생된다.
- 선택적 카메라 프레임이 있으면 실제 주행 화면도 재생된다.
- 재생 버튼만으로 로그가 자동으로 계속 재생된다.
- 완주나 리타이어 기록에서 자동 재생이 안전하게 멈춘다.
- 사용자 장애물과 충돌하면 공식 손상 규칙에 따라 상태가 변한다.
- 진행률·종료 사유·랩타임·손상·충돌 기록이 표시되고 저장된다.
- 기존 계약 테스트와 새 시뮬레이터/로그 재생 테스트가 통과한다.
- 제출용 `agent.py` 및 공식 물리 파일은 변경되지 않는다.
