# 극한 복합 기술형 트랙 생성기 설계 명세

상태: 대화 설계 및 서면 명세 사용자 승인 완료 (2026-09-20)

## 1. 목적과 배경

사용자는 자체 트랙을 에이전트의 일반화 점검과 로컬 주행 시뮬레이션에 활용하려 한다.
시드만 다른 비슷한 곡선이 아니라, 여러 S자 전환과 90도에 가까운 급격한 코너를 가진
새로운 레이아웃이 필요하다. 트랙은 기존 Box2D 시뮬레이터에서 주행 가능해야 하고,
로컬 실행 로그 제작 흐름과 기존 맵 저장 형식을 유지해야 한다.

현재 작업본의 `extreme_technical`은 기존 방사형 앵커 곡선 생성 방식을 확장한다.
코너 수를 12·14·16개로 요청할 수는 있지만, 측정한 코너 방향이 레시피와 맞지 않아
후보를 반복 거절한다. 재현한 테스트 시드 6개를 폭 8·9에서 각각 생성한 결과는 전부
12개 코너였다. 후보 진단에서는 14·16개도 유효한 경우가 있었지만, 고정 시드 세트에서는
재시도 후 결과가 12개로 쏠렸다. 따라서 재시도 횟수나 곡선 진폭만 조정하지 않고,
극한 트랙 전용의 구성적 경로 생성기를 설계한다.

## 2. 사용자 요구와 설계 가정

### 사용자 요구

- 시드마다 코스의 실제 구조가 달라질 것.
- 한 트랙 안에 여러 개의 빠른 S자 방향 전환과 90도에 가까운 급격한 코너가 있을 것.
- 고난도이되 기존 차량 물리와 시뮬레이터에서 실행 가능할 것.
- 트랙 및 장애물을 확인하고 로컬 실행 로그를 만들 수 있는 현재 흐름과 호환될 것.

### 설계 가정

- 극한 템플릿의 주요 코너 수는 12·14·16 중 하나로 생성한다.
- 직선 골격의 90도 회전은 차량이 주행할 수 있도록 최소 곡률 반경을 지키는 필렛으로
  둥글게 한다. 여기서 90도는 코너 구간 전체의 진행 방향 변화량을 뜻하며, 중심선에
  불연속적인 모서리를 만들겠다는 뜻은 아니다.
- S자 구간은 반대 방향으로 연속 전환하는 두 코너와 그 사이의 짧은 직선으로 정의한다.
  짧은 직선의 상한은 생성 입력의 `width` 3배다. 한 트랙에는 코너를 공유하지 않는 S자
  구간을 최소 3개 둔다.
- 생성 가능한 도로 폭은 기존 범위인 0.5–9.0을 유지한다. 장애물은 트랙 생성과 별도로
  현재 기능을 유지한다.
- 공식 대회 트랙과 공식 물리 구현은 바꾸지 않는다. 시뮬레이션과 에이전트 실행은 계속
  로컬에서 수행한다.

## 3. 목표와 비목표

### 목표

- 시드가 코너 수, S자 구간의 위치·방향·간격과 나머지 직선 길이를 결정한다.
- 각 트랙에 측정 기준상 75–105도 범위의 코너가 최소 3개 포함된다.
- 생성된 경로가 폐곡선이고 자기 교차·도로 경계 겹침이 없으며 현재 월드와 물리 검증을
  통과한다.
- 같은 버전·템플릿·시드·폭은 Python과 브라우저에서 같은 중심선과 메타데이터를 만든다.
- 저장된 이전 맵, 맵 JSON 스키마, 실행 로그 스키마와 로컬 주행 플로우를 유지한다.

### 비목표

- 공식 평가 트랙의 복제 또는 공식 트랙 편집.
- 물리 엔진, 차량 제어 방식, 에이전트 구조, 실행 로그 계약의 변경.
- 고도·경사·뱅킹·다중 차선·움직이는 장애물.
- 온라인 서버에서 차량 물리나 에이전트 추론을 실행하는 기능.
- 저장된 기존 맵의 중심선을 새 알고리즘으로 다시 생성하는 마이그레이션.

## 4. 생성 방식 검토

1. **기존 방사형 앵커 생성기 계속 보정** — 변경량은 작지만 곡선 앵커의 위치와 코너
   방향 측정이 서로 영향을 주어, 재시도에 따라 요청 코너 수가 바뀌는 문제가 확인됐다.
   시각적으로 직각에 가까운 구간을 보장하기 어려워 채택하지 않는다.
2. **소수의 수작업 경로를 시드로 회전·반전** — 경로 안전성은 통제하기 쉽지만, 시드가
   달라도 사실상 한정된 도안의 변형에 그쳐 일반화 점검 목표에 맞지 않는다.
3. **전용 직선 골격·필렛 생성기 (권장)** — 폐곡선의 직선 구간과 코너 배치를 구성적으로
   만든 뒤 각 코너를 곡률 제한이 있는 필렛으로 연결한다. 시드별 구조 차이와 코너 수를
   직접 보장하면서 기존 형상 검증을 재사용할 수 있다.

## 5. 설계

### 5.1 전용 경로 생성

- `extreme_technical`만 별도의 구성적 경로 생성기를 사용한다. 기존 템플릿의 중심선
  생성 방식은 이 변경으로 바꾸지 않는다.
- 생성기는 폐곡선의 직선 구간과 좌·우 90도 방향 전환으로 골격을 만든다. 독립적인
  무작위 꺾임을 이어 붙이지 않고, 코너 개수 변화량을 알고 있는 직교 루프·돌출·안쪽
  시케인 연산으로 폐합과 단순 다각형 조건을 구성 단계에서 유지한다. 정수 시드가
  12·14·16개 코너 중 하나, 코너 순서, S자 구간 위치와 직선 길이를 결정한다.
- 각 S자 구간은 서로 반대 방향인 두 코너와 그 사이 직선으로 구성한다. S자 구간은
  코너를 공유하지 않으며, 각 트랙에 최소 3개를 배치한다.
- 골격의 코너는 접선 연속인 필렛으로 치환한다. 필렛의 반경은 기존 회전 반경·도로 폭
  검증을 만족해야 하며, 곡선은 기존 중심선 샘플 간격 상한을 지킨다.
- 경로 구성 실패 시 후보를 제한된 횟수만큼 재시도할 수 있다. 재시도는 선택한 코너 수와
  필수 S자 구간 수를 유지해야 한다. 모든 후보가 실패하면 원인·템플릿·시드·폭을 포함한
  명시적 오류를 반환한다. 더 단순한 코스로 조용히 대체하지 않는다.

### 5.2 시드와 메타데이터

- 외부 난수나 네트워크 없이 결정적 32비트 난수 규약을 사용한다. Python과 JavaScript는
  난수 소비 순서, 기하 계산 순서, 좌표 양자화 규칙을 동일하게 구현한다.
- 생성기 변경으로 버전을 5로 올린다. 메타데이터에는 기존 `template`, `design_seed`,
  `generator_version`, `corner_count`, `corner_sequence`, `corner_turn_degrees`,
  `corner_radius_widths`와 함께 `s_section_count`, `near_90_corner_count`를 기록한다.
- 화면 요약은 코너 수와 S자 구간 수, 90도 급코너 수를 표시해 사용자가 실제 생성
  결과를 바로 확인할 수 있게 한다.
- 기존 맵은 저장된 중심선을 그대로 사용한다. 버전 상승이 이전 맵의 형상을 바꾸지 않는다.

### 5.3 구성 요소와 인터페이스

- `local_simulator/track_generator.py`: Python 기준 생성기, 난수 규약, 필렛 처리와 기존
  형상 검증을 연결한다.
- `web_simulator/app.js`: 웹 단독 생성 경로에 동일한 결정적 알고리즘을 구현한다.
- `web_simulator/index.html`: 기존 극한 템플릿 선택을 유지하고 생성 결과 요약을 표시한다.
- API와 CLI는 기존 템플릿 필드·인자를 유지하며 `extreme_technical`을 생성한다.
- 맵 JSON 스키마와 실행 로그 스키마는 바꾸지 않는다. 추가 생성 정보는 기존 generator
  메타데이터 영역에만 기록한다.
- 서버를 사용할 수 없어 브라우저 생성 경로를 쓰는 경우에도 같은 알고리즘 결과를 만든다.
  서버가 트랙의 형상 검증 오류를 반환한 경우에는 브라우저가 다른 코스로 대체하지 않고
  그 오류를 사용자에게 보여준다.

## 6. 안전성과 오류 처리

- 기존 유한 좌표, 최소 점 수, 최소 총 길이, 자기 교차, 도로 경계 교차, 최소 곡률 반경,
  최대 중심선 점 수 검증을 유지한다.
- 중심선 샘플 간격은 기존 상한인 4 월드 단위를 넘지 않는다. 생성 형상은 기존 월드
  경계 안에 있어야 한다.
- 폭 0.5–9.0 범위만 생성기에 허용한다. 범위 초과 또는 안전 검증 실패는 명시적 오류다.
- 제한된 재시도 이후에도 유효한 트랙이 없으면 API·CLI·브라우저에서 실패를 전달한다.
  코너 수 축소, 템플릿 변경, 타원 대체로 오류를 숨기지 않는다.

## 7. 검증과 완료 기준

1. 같은 입력은 반복 실행 시 Python과 브라우저에서 같은 중심선 fingerprint와 메타데이터를
   만든다. 비교 시드에는 0, 1, 42, 73, 300, 1200, 2³²−1을 포함한다.
2. 고정 테스트 시드 집합이 12·14·16 코너를 모두 생성하고, 각 생성 결과는 선언한 코너
   수·S자 구간 수·근 90도 코너 수와 일치한다.
3. 각 결과에는 코너를 공유하지 않는 S자 구간이 최소 3개 있고, 측정된 진행 방향 변화가
   75–105도인 코너가 최소 3개 있다.
4. 폭 8.0의 연속 시드 0–99가 모두 생성·검증을 통과한다. 폭 0.5와 9.0에서는 각 코너
   수를 대표하는 고정 시드로 폭 경계 검증을 수행한다.
5. 각 코너 수의 대표 트랙은 기존 Box2D 커스텀 환경에서 로드되고 reset 및 최소 1회
   step에 성공한다.
6. 웹 API, CLI, 브라우저 미리보기에서 성공·실패가 일관되며 검증 실패가 다른 레이아웃으로
   조용히 대체되지 않는다.
7. 저장된 이전 맵과 기존 맵·로그 스키마 호환 테스트가 계속 통과한다.

## 8. 위험과 대응

- **직선 골격의 자기 교차 또는 좁은 여유 공간:** 구성 단계에서 코너 간격·필렛 반경을
  제한하고, 최종 중심선 및 도로 경계 검증으로 거부한다.
- **폭이 클 때 S자 구간이 월드에 맞지 않음:** 직선 길이와 배치를 폭에 맞춰 선택하고,
  불가능하면 명시적으로 실패한다. 폭을 무시하거나 쉬운 트랙으로 바꾸지 않는다.
- **Python과 JavaScript의 부동소수점 결과 불일치:** 명시적 PRNG와 계산 순서·양자화 규칙,
  고정 입력 parity 테스트를 유지한다.
- **성공은 하지만 실제로 주행하기 지나치게 어려움:** Box2D 환경 생성 및 step 테스트를
  통과 기준에 포함한다. 주행 난도 자체를 물리 엔진 변경으로 완화하지 않는다.

## 9. 명세 범위

이 명세는 `extreme_technical` 자체 트랙 생성 방식만 다룬다. 맵 편집, 장애물, 로컬
시뮬레이션, 실행 로그의 기존 계약은 유지한다. 구현 계획과 구현은 이 서면 명세의 사용자
검토·승인 후 진행한다.
