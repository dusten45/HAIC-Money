# 다중 코너 자체 트랙 생성기 설계 명세서

상태: 사용자 승인 완료 (2026-09-20)

## 1. 목적과 배경

현재 자체 트랙 생성기는 `oval`, `s_curve`, `hairpin`, `chicane` 네 템플릿을 제공한다.
그러나 세 템플릿은 단일 타원형 곡선을 조금씩 변형하고, 헤어핀은 긴 직선 두 개와
반원형 회전부를 잇는 형태다. 시드가 달라도 코스의 기본 인상은 크게 바뀌지 않는다.

사용자가 원하는 것은 코너의 개수와 순서가 달라지고, 한 바퀴의 레이아웃 자체가 서로
다르게 느껴지는 코스다. 또한 자체 트랙을 에이전트의 과적합 방지·일반화 점검에 사용할
예정이므로, 단순한 크기 변화만으로는 성공으로 보지 않는다.

이 명세는 기존 커스텀 맵 흐름과 저장 형식을 유지하면서, 다중 코너와 눈에 띄는 레이아웃
차이를 만드는 결정적 생성기를 정의한다. 기존 자체 트랙·맵 파일은 저장된 중심선을 그대로
사용하며, 본 명세는 새로운 생성 결과에만 적용한다.

## 2. 사용자 요구와 설계 가정

### 사용자 요구

- 한 트랙에 여러 코너가 있고, 트랙마다 새로운 인상을 줄 것.
- design seed로 재현 가능하면서 서로 다른 시드에서는 실질적인 레이아웃 차이가 날 것.
- 웹에서 생성·편집·저장하고, 로컬 실행 로그를 만들 수 있는 기존 흐름과 이어질 것.

### 설계 가정

- 공식 대회 트랙과 공식 물리 코드는 변경하지 않는다.
- 맵 JSON schema 2와 현재 `/api/maps/generate` 계약을 유지한다.
- 타원형은 쉬운 기준 코스로 남기고, 나머지 생성 스타일을 다중 코너형으로 확장한다.
- 장애물 배치는 트랙 생성과 분리된 현재 기능을 유지한다.
- 시뮬레이션과 Agent 추론은 계속 로컬에서 수행한다.

## 3. 목표와 비목표

### 목표

- 시드가 레이아웃의 코너 수, 코너 종류와 배열, 직선 길이, 코너 반경에 영향을 준다.
- 플로우형, 헤어핀형, 시케인형, 복합 기술형이 화면에서도 구분된다.
- 같은 생성기 버전·템플릿·시드는 Python API와 브라우저 단독 생성에서 같은 중심선을
  만든다.
- 생성된 중심선은 폐곡선이며, 자기 교차나 도로 폭과 맞지 않는 급격한 곡률을 만들지 않는다.
- 기존 맵 파일, 직접 편집, 장애물 편집, 로그 재생 기능은 호환된다.

### 비목표

- 고도, 경사, 뱅킹, 여러 차선 또는 움직이는 장애물.
- 공식 트랙의 복제나 공식 평가에 사용할 트랙 생성.
- 온라인에서 물리를 실행하거나 Agent를 서버에서 실행하는 기능.
- 저장된 이전 맵의 중심선을 새 생성 알고리즘으로 자동 교체하는 기능.

## 4. 생성 방식 검토

1. **현재 타원형 곡선의 진폭만 키우기** — 구현은 간단하지만 코스의 뼈대가 계속
   타원으로 보여 사용자가 지적한 단순함과 과적합 위험을 충분히 해결하지 못하므로
   채택하지 않는다.
2. **수작업 레이아웃 몇 개를 회전·반전해 제공하기** — 품질을 통제하기 쉽지만 서로
   다른 시드를 만들어도 사실상 소수 도안에 머물러 과적합 방지 목표와 맞지 않는다.
3. **결정적 구간 조합 생성기 (권장)** — 시드로 코너 구간의 개수·종류·순서와
   직선·반경을 정하고, 부드러운 폐곡선 중심선으로 잇는다. 기존 자기 교차 검사와
   도로 폭 검사를 통과하지 못하면 제한된 재생성을 시도한다.

## 5. 제안 동작

### 5.1 템플릿

기존 `oval`, `s_curve`, `hairpin`, `chicane` ID는 유지한다. 새 `technical` 템플릿을
추가한다. 과거에 생성된 맵의 `template` 값과 저장된 geometry는 계속 읽을 수 있어야 한다.

| 템플릿 | 의도된 주행 인상 | 레이아웃 조건 |
| --- | --- | --- |
| `oval` | 쉬운 기준 코스 | 네 개의 넓은 코너 구간, 비교적 긴 직선 |
| `s_curve` | 흐르는 연속 코너 | 서로 반대 방향으로 이어지는 S 구간을 포함한 6–8개 주요 코너 |
| `hairpin` | 제동과 탈출 가속 | 긴 직선과 최소 두 개의 급격한 헤어핀을 포함한 6–9개 주요 코너 |
| `chicane` | 좌우 빠른 전환 | 최소 두 개의 좌우 전환 조합을 포함한 7–10개 주요 코너 |
| `technical` | 복합·기술 코스 | 서로 다른 반경의 코너와 직선이 섞인 9–12개 주요 코너 |

주요 코너 수는 제어점 개수가 아니라 생성 레시피의 코너 구간 수다. 미세한 spline
샘플점 수가 코너 수로 표시되지 않도록 한다.

### 5.2 시드와 재현성

- 생성은 명시적인 32비트 정수 seed와 템플릿을 사용하며 외부 난수·네트워크에 의존하지
  않는다.
- Python과 JavaScript 양쪽에서 동일한 명시적 32비트 PRNG와 같은 구간 생성 순서를
  사용한다. 런타임 기본 난수기의 차이에 결과를 맡기지 않는다.
- 생성기 정보에는 `template`, `design_seed`, `generator_version`, `corner_count`,
  `corner_sequence`를 기록한다. 화면에도 코너 수와 대표 조합을 짧게 표시해 현재
  미리보기의 성격을 알 수 있게 한다.
- 생성기 알고리즘을 바꾸면 버전을 올린다. 저장된 geometry를 보유한 이전 맵은
  재생성 없이 그대로 로드한다.

### 5.3 중심선 구성

- 시드로 폐곡선의 코너/직선 레시피를 만든 뒤, 곡률을 부드럽게 잇는 곡선으로
  변환하고 월드 좌표 중심선을 길이에 따라 샘플링한다.
- 각 레이아웃은 화면에서 형태를 구분할 수 있도록 길이·폭 비율, 코너 밀도, 직선
  구간을 다르게 한다. 위치·방향의 미세한 변형만 있는 동형 트랙은 다양성으로 세지 않는다.
- 시작선은 중심선의 유효한 샘플점에 두고, 주행 방향은 기존 `start_index`와
  `direction` 규약을 따른다.
- 생성 실패를 무한 재시도하지 않는다. 제한된 횟수 안에 유효 트랙을 만들지 못하면
  원인을 포함한 명시적 오류를 반환한다.

### 5.4 형상 안전성

- 기존 최소 점 수, 유한 좌표, 0 길이 구간, 최소 총 길이, 중심선 자기 교차 검사를
  유지한다.
- 선택한 반폭에 비해 코너 반경이 너무 작거나, 평행 도로 경계가 서로 겹칠 수 있는
  구간을 거부한다.
- 생성기는 고정 플레이 영역 안에서 안전한 다중 코너를 보장하는 도로 반폭 0.5–9만
  허용한다. schema가 허용하는 더 큰 폭의 저장 맵을 불러오는 것은 가능하지만,
  생성기는 이를 단순 타원으로 대체하지 않고 명확한 범위 오류를 반환한다.
- 저장 전에 유효성을 검사하고, 대표 생성 결과는 실제 Box2D 커스텀 환경에서 맵 생성,
  reset, 1스텝 실행까지 통과해야 한다.
- 검증을 위해 지나치게 좁거나 자기 교차하는 형상을 자동으로 단순한 타원으로 대체하지
  않는다. 실패는 숨기지 않고 보고한다.

## 6. 구성 요소와 호환성

- `local_simulator/track_generator.py`: 정식 구간 레시피, PRNG, 중심선 생성, 검증.
- `local_simulator/api.py` 및 CLI: 기존 템플릿 인자/필드를 유지하고 `technical`을 추가.
- `web_simulator/index.html` 및 `app.js`: 새 템플릿 선택을 표시하고 브라우저 단독
  fallback에서 Python과 동일한 seed/중심선을 생성하며 코너 요약을 보여준다.
- 테스트: 생성기 단위 테스트, Python–JavaScript 고정 입력 동등성 테스트, 커스텀 환경
  실행 테스트.
- 맵 schema와 주행 로그 계약은 변경하지 않는다. 기존 `oval/s_curve/hairpin/chicane`
  저장 맵은 로드 가능한 상태로 둔다.
- 장애물은 현재처럼 `progress/lateral/radius`로 별도 추가한다. 새 트랙을 만들었다고
  장애물이 자동 생성되지는 않는다.

## 7. 검증 및 완료 기준

1. 같은 generator version·template·seed는 완전히 같은 JSON 중심선과 fingerprint를
   만든다.
2. 같은 템플릿에서 다수의 고정 시드를 생성했을 때 레이아웃 fingerprint와 코너 레시피가
   서로 달라지고, 각 템플릿의 코너 조건을 충족한다.
3. 예를 들어 0–99 범위의 연속 시드 집합을 생성해 모든 결과가 형상 검증을 통과한다.
   실패 시에는 임의로 씨드를 건너뛰지 않고 원인을 테스트에서 확인할 수 있어야 한다.
4. Python API 생성과 브라우저 fallback이 같은 입력에서 같은 중심선을 만든다.
5. 모든 템플릿의 대표 맵이 커스텀 Box2D 환경에서 생성되고 reset 및 1회 이상 step된다.
6. 저장된 schema 2 맵과 schema 1 로그 호환 테스트가 계속 통과한다.
7. 브라우저 미리보기에서 타원 기준형과 다중 코너형이 구분되고, 새 트랙 생성 후에만
   선택 템플릿이 현재 맵에 반영되는 동작을 명확히 한다.

## 8. 위험과 대응

- **자기 교차·도로 경계 중첩:** 코너 간 최소 거리와 반경 제약, 기존 교차 검사,
  제한된 재생성 및 Box2D 실행 검증으로 방지한다.
- **시드는 다른데 비슷한 레이아웃:** 크기 차이가 아니라 코너 레시피의 차이를 테스트하고,
  레시피가 충분히 다양하지 않으면 실패로 처리한다.
- **Python/API와 브라우저 fallback 불일치:** 공통 PRNG 규약 및 고정 시드 동등성 테스트로
  방지한다.
- **새 생성기 버전으로 기존 맵이 바뀐 것처럼 보임:** 생성기 버전을 저장하고,
  geometry가 이미 들어있는 맵은 재생성하지 않는다.
