# 앞보기·미니맵 입력 점검

## 사용자 요구와 판정

사용자는 현재 제어가 근시안적으로 보이며, 먼 도로 또는 전체 미니맵을 이용해 미리 조향·가감속해야 한다고 제안했다. 코드 점검 결과 이 지적에는 근거가 있다. 기존 안정화 조향을 그대로 두고 페달만 확장한 앞선90회 비교는 장거리 경로 계획을 구현한 것이 아니다. 이 점을 이후 성능 설명에서 명확히 구분한다.

이번 작업은 소스·관측 계약 조사와 후속 설계이며 새 주행을 수행하지 않았다.

## 확인된 입력

2026-09-29 공식 Participants README와 env_wrapper.py, core/vendor/car_racing.py를 다시 읽었다.

- Agent 입력은 최근4개84×84흑백 이미지다. 공식 renderer는 차량 중심 도로·장애물과 하단 계기판을 그리며, 별도 전체 미니맵을 합성하지 않는다.
- reset에서50raw ticks를 무동작으로 진행한 뒤 마지막 이미지를4번 복제해 반환한다. 초기 광각 줌 화면은 이 이전에 지나가므로 현재 reset 입력에서 전체 지도를 얻을 수 없다.
- 관전 사이트의 전체 트랙 표시가 있다 해도 그것이 Agent observation에 포함된다는 뜻은 아니다. 라이브 사이트의 별도 관전 UI는 이번에 검증하지 않았다.
- 우선순위 사이트 ships-duo-ethical-saver는 web tool에서 접근 실패. 외부 제출·업로드 없음.

## 실제로 사용한 시야

정상 줌에서 카메라상 차체 원점은 약(42,63), 세로1.701pixel/내부거리단위다. 시간은 직선·현재속도70·일정속도 가정이다. 곡선을 따라가는 거리나 충분한 제동 여유를 의미하지 않는다.

| 처리 | 이미지 행 | 전방거리 | 도착 시간 |
|---|---:|---:|---:|
| 주 조향의 가까운 점 | 54 | 5.29 | 0.076초 |
| 주 조향의 앞 점 | 42 | 12.35 | 0.176초 |
| 기존 도로 검출 최원거리 | 30 | 19.40 | 0.277초 |
| 새 가감속 corridor 최원거리 | 10 | 31.16 | 0.445초 |
| 이미지 최상단의 기하학적 한계 | 0 | 약37.04 | 약0.529초 |

근거: pixel_features.road_centers는 rows54,50,46,42,38,34,30을 추적한다. corridor_agent의 주 조향은 rows42,54이며 fixed_high_speed_runtime의 채택된 damping은 이전 frame의row42변화를 추가한다. preview_pedal 계열은 가감속에만 geometric_passing._corridor(rows54..10)를 사용한다. 원거리 이미지가 있어도 주 조향은 그 경로를 미리 추종하지 않는다.

또한 각 행에서 이전 중심 주변 ±17pixel만 추적하는 구조는 도로를 대략 x=f(y)로 취급한다. 급커브에서 도로가 화면 옆으로 이어지거나 다른 도로가 가까이 보이는 경우, 단순 행 평균으로 연결관계를 잃을 수 있다. 이는 코드 구조상 한계이며 모든 실패가 그 때문이라는 증거는 아니다.

R2/R3의 기억은 제약까지 거리에서 speed×dt를 빼고 일정 시간 유지하는 방식이다. 좌우 위치와 카메라 회전을 변환하는 지도 기억이 아니므로 이를 '전체 맵을 기억한다'고 표현하면 안 된다.

## 다음 구현 방향

기존 연구의 페달 상수 조정보다 아래 관측/경로 가설을 우선한다. user standing authorization은 유지하되 새로운 소스·계획 해시와 별도 설계/실행 이벤트를 기록한 뒤 평가한다. 현재는 설계 초안이며 성능 개선 주장이 아니다.

1. **화면 전체의 연결된 도로 추적:** HUD를 제외한 도로 영역을2차원으로 찾고 차량 앞 도로와 연결된 경로를 추적한다. 단순히 가장 먼 회색 영역을 선택하지 않는다. 급커브가 화면 옆으로 이어지는 형태와 인접하지만 다른 구간의 도로를 구분한다.
2. **거리별 역할을 나눈 선행 조향:** 가까운 경로는 현재 횡오차 보정, 중간 경로는 따라갈 방향, 먼 경로는 다음 코너 방향·강도와 감속 준비에 쓴다. 급히 먼 점 하나로 꺾는 방식과 구분하고 실제 조향 지연을 포함한다.
3. **이전 관측을 회전·이동시킨 국소 지도:** 픽셀 흐름 또는 검증된 HUD회전·속도 추정으로 이전 도로 점들을 현재 차체 좌표로 변환한다. 보였던 구간의 신뢰도·나이를 유지하고 관측과 충돌하면 폐기한다. 보지 못한 최초 구간을 이미 아는 것처럼 채우지 않는다.
4. **경로와 속도 공동 계획:** 같은 도로/회피 경로를 조향과 페달이 공유한다. 해당 경로의 곡률·장애물·시야 끝·조향응답을 바탕으로 가능한 가속과 필요한 제동을 계산한다. 이전 실험처럼 먼 점으로 페달만 계획하고 조향은 가까운 점에만 맡기는 불일치를 줄인다.

각 방향은 독립 후보로 활성화부터 확인하고 최대8후보/방향당2개 원칙을 지킨다. 우선 소비한 TRAIN으로 도로 연결 추적의 누락/잘못된 분기, 유효 전방거리, 코너 방향을 처음 검출한 시점, 조향 시작 시점, pedal개입을 측정한다. 정답 위치·지도·회전은 평가 전용이며 Agent에 전달하지 않는다. 이후 동일조건 완주율 우선/동률이면 랩타임을 비교한다. 차선 밖 허용 여부를 임의로 더 엄격하게 만들지 않는다.
