# 고속 고정·도로 이탈 제한 조향 실험

## 설정과 실행 범위

사용자 요청대로 목표 속도를 60으로 고정하고 최종 가속·브레이크 명령의 결정권을 별도 속도 제어기에 뒀다. 60은 기존 픽셀 속도 추정기의 단위이며 km/h나 기존 대비 정확히 두 배라는 뜻이 아니다. 커브·장애물·도로 인식 상태가 목표 속도를 낮출 수 없다. 목표 초과 시 제동은 허용하지만 감속을 통해 완주한 주행은 고속 유지 조건을 통과하지 못한다.

성공 조건은 실제 완주, 충돌·무효 행동 0, 출발 25결정 이후 목표의 90% 이상 속도를 90% 이상 유지, 차량 중심의 도로 밖 시간 1% 이하, 연속 이탈 8물리 프레임 이하를 모두 만족하는 것이다. 속도는 픽셀과 평가용 실제 속도를 각각 판정한다. 도로 이탈은 매 물리 프레임의 실제 도로 도형 포함 여부로 측정한다. 차체 중심 판정이므로 모든 바퀴가 항상 도로 안이라는 뜻은 아니다. 바퀴 접촉 수도 원본에 기록했다. 내부 상태는 평가에만 쓰고 에이전트에는 전달하지 않았다.

학습용 트랙 1–3 × 시드 38200–38201, 여섯 조건이다. 첫 배치 30회, 경로 추종 구현 수정 6회, 도로 경계 개입 후속 6회로 **총 42회** 실행했다. 후속 12회는 같은 학습 조건의 재실행이며 독립된 새 성능 증거가 아니다. 다른 공개 순위나 선택 ZIP과 직접 비교한 실험도 아니다.

## 결과

| 조향 방식 | 일반 완주 / 6 | 고속·도로 조건까지 통과 / 6 |
|---|---:|---:|
| 같은 고속의 기존 corridor 조향 | 0 | 0 |
| 더 먼 도로 선행 조향 | 0 | 0 |
| 곡률 변화 보정 | 0 | 0 |
| 화면 움직임을 이용한 흔들림 억제 | 3 | 0 |
| 이미지 경로 추종, 원본 구현 | 0 | 0 |
| 이미지 경로 추종, 포화 계산 수정 | 0 | 0 |
| 흔들림 억제 + 도로 밖 방향의 장애물 조향 제한 | 2 | 0 |

흔들림 억제 방식의 세 완주는 각각 트랙1/38200 **17.34초**, 트랙2/38201 **17.54초**, 트랙3/38200 **17.24초**다. 모두 충돌 0, 출발 제외 픽셀·실제 속도 유지율 100%였다. 그러나 도로 이탈 비율은 각각 **4.38%, 2.39%, 4.87%**, 최장 연속 이탈은 **13, 8, 21프레임**이므로 성공으로 인정하지 않았다. 목표 속도를 낮추거나 이탈 허용치를 넓히지 않았다.

코드 검토에서 경로 추종의 조향 포화 계산 오류를 발견했다. 원본 코드와 결과를 보존하고 별도 하위 클래스로 수정했으며, 같은 여섯 조건 재실행도 0/6이었다. 따라서 원본 실패를 의도한 경로 추종 방식의 증거로 단정하지 않는다. 수정 실행은 원본 control의 첫 열 행동·위치 해시와 여섯 조건 모두 일치했다.

후속 도로 경계 개입은 58회 조건에 들어왔고 실제 조향은 57회 바뀌었다. 1/38200에서 첫 이탈은 원래 물리 프레임207에서283으로 늦춰졌으나 전체 이탈은 악화했다. 기존 미완주 2/38200을 완주했지만 기존 완주 두 조건을 잃었다. 기존 완주 세 개 중 하나만 보존했으므로 개선이 아니다. 이는 장애물 조향을 단순히 제거하는 규칙만으로 문제를 해결할 수 없다는 국소 증거이며 고속 주행 전체의 불가능성을 뜻하지 않는다.

## 검증과 한계

- 첫 배치 여섯 조건의 공통 출발 해시가 모두 일치했다. 두 후속 실행도 각각 원본 control/damping과 해시가 일치했다.
- 원본 에피소드 파일 해시를 확인했고, 후속 실행의 승인 manifest에 원본 비교 보고서 해시를 고정했다.
- 속도 제어·포화 수정·회피 개입 관련 집중 확인 4개와 설정 검증이 통과했다. 실제 주행은 모두 등록된 로컬 프로필에서 실행했다.
- `pixel_physical_speed_mae`는 행동 전 픽셀 속도와 행동 후 실제 속도의 시간차가 있는 차이다. 센서 자체의 보정 오차라고 해석하면 안 된다. 성공 판정은 이 값에 의존하지 않는다.
- 기존 전체 봇의 대체 후보나 학습 완료 모델이 아니다. 네 가지 메커니즘을 진단한 코드이며 패키지·사이트 업로드·공식 제출·선택 모델 교체는 없다.
- 최신 공식 규칙 인증은 하지 않았으므로 rule_compliance는 UNKNOWN이다. 세 실행 모두 세 게이트 검토 후 STOPPED, released=false다.

## 다음 개선 지점

고속 목표와 성공 기준은 유지한다. 원래 damping 제어기와 실패 직전까지 동일한 행동으로 진입한 뒤, 장애물을 피하면서 도로 안에 남는 조향 경로를 비교하는 진단이 필요하다. 지금의 전역적인 조향 덧셈·회피 제거는 한 구간을 고쳐도 다른 구간을 깨뜨린다. 다음 단계는 실패 직전 진입 상태를 고정한 구간별 행동 비교와 성공 조향 데이터 확보다. 이 후속 구간 실험은 아직 실행하지 않았다. 이 문서가 백그라운드 반복 실행을 의미하지는 않는다.

## 사용자 기준 정정과 코드 제공 요청

이후 사용자는 위의 짧은 도로 이탈 정도는 허용하며 기존 기준이 과도하게 엄격했다고 명시했고, 원래 damping 코드를 제출용으로 요청했다. 따라서 1%/8프레임은 향후 이 후보를 전달하지 못하게 하는 기준으로 적용하지 않는다. 역사적 엄격 판정과 원본 결과는 보존하되, 현재 설명은 일반 완주3/6과 미완주3/6으로 한다. 완주한 세 셀의 이탈만으로 실격·부적합이라 단정하지 않는다. 더 넓은 모든 이탈 범위를 검증했다는 뜻도 아니다. 원래 damping의 동일 소스를 로컬 ZIP으로 묶고 전체 여섯 소비 셀에서 패키지 동일성을 확인하는 별도 실행을 등록했다. 기준 ZIP 자동 교체나 공식 제출은 아니다.
