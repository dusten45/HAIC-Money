# 출발 가속과 선행 조향 분리 실험 — revision 3

## 근거

revision 1은 출발 가속 뒤의 직선 추가 가속 560회와 함께 진단 완주가 10/12로 줄었다. revision 2는 직선 추가 가속을 제거해 진단 12/12, 새 tune 11/12 동률 완주를 얻었지만 커브 제동 121회가 동작하며 완주 중앙시간이 대조군보다 0.04초 느렸다. 정확한 기록은 `docs/experiments/launch-preview-20260929.md`에 있다. 아직 출발 가속과 앞보기 **조향 자체**의 결합 이득을 분리해 측정하지 못했다.

## 고정할 revision 3

`ObstacleFullRoadGuardAgent → LaunchSurgeAgent → AnticipatoryBendAgent`만 결합한다. revision 2의 제동 wrapper를 제거한다. 출발 가속 `0.45/34/18`과 앞보기 조향의 화면 기준·상한은 변경하지 않는다. 새로운 gas 또는 brake 명령을 추가하지 않는다. 장애물 진단은 원래 선택된 guard가 읽고, 앞보기 조향은 장애물이 보이면 기본 행동을 보존한다. 추론 입력은 픽셀과 기본 행동뿐이다.

## 순서와 판정

정확한 새 ZIP의 활성화는 이미 소비된 2900–2903에서 확인한다. 출발 가속이 유지되고 앞보기 조향이 실제로 발생하며 후보만 미완주하지 않아야 새 tune을 연다. 새 tune은 트랙 1–3 × seed 7024–7027, held-out 7028–7031, confirmation 7032–7035로 사전 예약한다. 각 블록은 양팔 각 12셀, 최대 2,000 decision/episode, 로컬 Linux CPU 2개·2 GiB·1,800초다. 실행 직전에 V2 manifest와 다른 계획 예약의 중복을 재확인한다. 완료율 열세가 있으면 시간을 비교해도 채택하지 않는다. 완료율이 같을 때만 완주 중앙시간과 등록된 후순위 지표를 비교한다. tune 열세면 뒤 블록을 열지 않는다.

각 plan hash에 설계·실행 이벤트를 별도로 기록하며, 사용자의 2026-09-29 상시 로컬 승인을 인용한다. 사이트 업로드·공식 제출·모델 확정은 포함하지 않는다.
