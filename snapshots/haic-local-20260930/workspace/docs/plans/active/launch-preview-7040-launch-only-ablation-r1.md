# 후반 이탈의 출발 가속·앞보기 조향 분리 — 소비 셀 ablation

## 관측

`launch-preview-7040-boundary-trace-20260929`의 정확한 ZIP 재주행에서 결합 후보는 트랙 3/7040 진행률 91.62%에서 다시 도로를 이탈했고 선택된 full-road-guard는 완주했다. 후보의 앞보기 조향은 여섯 번, 그중 후반 진행률 약 89.5%에서 조향을 −0.03에서 −0.09로 바꿨다. 이후 장애물 영상 신호가 보이는 구간에서 두 차량의 조향이 달라졌다. 이 결과는 시간적 선행과 경로 차이를 보여 주지만 출발 가속과 조향 중 원인을 분리하지 못한다.

## 고정 ablation

결합 후보에서 **앞보기 조향만 제거한 기존 정확한 launch-only ZIP** SHA-256 `4043993d9901d58b126980b7bafe4f0154305c6a0bf01e1e7e5bc02aacec2389`을 현재 선택 ZIP SHA-256 `5c55670ab5aef4bf64115909792650a5e76bc3576a64f3aaeb3780efabc18e40`과 이미 소비된 7040–7043 전체에 다시 비교한다. `training.compare_launch_surge_package`의 고정 압축 해제 비교를 사용한다. 주된 진단은 트랙 3/7040의 결승선 통과, 진행률과 평가 trace의 경로다. 나머지 셀은 같은 조건에서 출발 가속의 일관성을 확인하는 부가 진단이다. 이 반복은 새 tune/held-out이나 SOTA 근거가 아니다.

트랙 3/7040에서 launch-only도 실패하면 선행 조향만 탓할 수 없다. launch-only가 완주하면 앞보기 개입이 실패에 기여했을 가능성이 커지지만, 결정적 인과 판별에는 같은 출발·기본 상태에서 한 지점의 개입만 제거한 후속 진단이 필요하다. 두 팔 각 12셀, 셀당 2,000 decision, 로컬 Linux CPU 2개·2 GiB·1,800초. 계획 해시마다 2026-09-29 사용자 상시 로컬 승인을 인용해 설계·실행 이벤트를 별도 기록한다. 외부 행동은 없다.
