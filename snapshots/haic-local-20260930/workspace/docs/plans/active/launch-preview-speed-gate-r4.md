# 출발 가속·선행 조향의 고속 개입 제한 — revision 4

## 근거

앞보기 조향 결합 ZIP은 launch-only ZIP보다 새 tune/held-out/confirmation에서 완주를 유지하거나 높였으나, 현재 선택 ZIP과 새 7040–7043에서 11/12 대 12/12로 거절됐다. 후보 전용 실패 3/7040은 진행률 89.5%에서 앞보기 조향이 −0.03을 −0.09로 바꾼 뒤 후반 도로 이탈로 이어졌다. 그때 픽셀 속도는 약 47.3이었다. 반대로 앞보기 조향이 launch-only의 실패를 복구한 3/7041에서는 초반 진행률 5.1–5.4%에 픽셀 속도 약 42.3에서 두 번 개입했다. 두 셀의 굴곡 크기는 겹쳐 굴곡 크기만으로 구분할 근거가 약하다. 근거는 `docs/experiments/launch-preview-20260929.md`의 정확한 ZIP trace다. 단일 셀에서 고속 개입이 모든 실패의 원인이라고 일반화하지 않는다.

## 한 가지 수정

원래 `LaunchSurgeAgent`의 초기 가속과 `AnticipatoryBendAgent`의 기존 조향 기준을 유지한다. **픽셀 추정 속도가 45를 초과할 때만** 앞보기 조향을 건너뛰고 상속된 출발·guard 행동을 반환한다. 속도 45 이하에서는 기존 앞보기 조향 코드를 바이트 수준으로 그대로 호출한다. 새 gas·brake 명령과 simulator 위치·지도 입력은 추가하지 않는다. 45는 위 두 소비 셀에서 관측된 42.3과 47.3 사이의 단일 사전 고정 경계로, 임계값 sweep을 하지 않는다.

## 순차 판정

먼저 소비된 7040–7043에서 고속 조향 억제 활성, 3/7040의 결승선 복구, 3/7041의 결승선 유지, 출발 가속 유지, 무효 행동 0을 확인한다. 하나라도 실패하면 새 tune을 열지 않는다. 진단이 통과하면 새 tune 트랙 1–3 × seed 7052–7055, held-out 7056–7059, confirmation 7060–7063을 예약한다. 각 블록은 후보와 원래 조향 결합 ZIP 각 12셀을 같은 순서 교대로 달리고, 완료율 우선, 동률일 때 중앙 랩타임과 등록된 후순위 지표를 본다. 현재 선택 ZIP과의 별도 비교 없이 선택 모델을 교체하지 않는다. 실행 직전 다른 V2 manifest와 계획 예약을 다시 확인한다. 최대 2,000 decision/episode, 2 CPU/2 GiB, 1,800초/블록이다.

사용자의 2026-09-29 상시 로컬 승인에 근거해 각 exact plan hash의 설계·실행 이벤트를 별도 기록한다. 대회 사이트 업로드·공식 제출·모델 확정은 포함하지 않는다.
