# HAIC 로컬 작업 전체 보존 (2026-09-30)

이 스냅샷은 로컬 HAIC에서 작업한 코드, 문서, 설명서, 실험 설정, 원본 주행 기록, 모델/체크포인트, 제출물, 중간 실험 폴더를 복원하기 위한 자료입니다. 기존 원격 저장소의 다른 연구 작업을 덮어쓰지 않도록 별도 경로에 보존했습니다.

## 어디에 있나요?

- **[workspace/](workspace/)**: 코드·문서·설명서 및 별도 작업 디렉터리의 파일. 원래 로컬 경로를 그대로 유지합니다.
- **[GitHub Release의 전체 원자료](https://github.com/dusten45/HAIC-Money/releases/tag/haic-local-backup-20260930)**: `artifacts/`, `runs/`, `submissions/`, `tmp/`, `.superpowers/`의 압축파일입니다. 원본 경로는 ZIP 내부에 유지됩니다.
- **[manifest.json](manifest.json)**: 보존된 모든 파일의 경로·크기·SHA-256·저장 위치와 제외 내역입니다.
- **[SHA256SUMS](SHA256SUMS)**: 각 Release 첨부파일의 SHA-256입니다.

일부 `tmp/` 자료는 다른 파일과 중복된 동결본입니다. 파일을 임의로 합치거나 지우지 않고 보존했습니다. 현재 폴더는 포렌식 수준의 전체 디스크 이미지가 아니라 프로젝트 작업 파일의 스냅샷입니다.

## 복원

1. 새 빈 폴더를 만듭니다. 현재 연구 폴더 위에 바로 덮어쓰지 마세요.
2. `workspace/`의 내용을 새 폴더로 복사합니다. 숨김 경로도 포함합니다.
3. 위 Release의 `haic-*.zip` 파일들을 내려받고 `SHA256SUMS`와 해시를 비교합니다.
4. 모든 ZIP을 **같은 새 폴더**에 풉니다. 각 ZIP에는 원래 최상위 경로가 포함되어 있습니다.
5. `manifest.json`의 각 `path`에 해당하는 파일의 바이트 수와 SHA-256을 확인합니다.

`.worktrees/` 내부 프로젝트는 실제 파일로 보존했지만 Git 연결 정보는 제외했습니다. 필요한 경우 별도 Git 저장소로 다시 초기화하세요. 파이썬 환경과 캐시는 저장하지 않았으므로 해당 프로젝트의 의존성 파일로 환경을 다시 구성해야 합니다. 이 스냅샷의 루트 agent가 최신 제출 후보라는 보장은 없습니다. 제출할 때는 [검증된 Arrival-speed ZIP](../../releases/arrival-speed-20260930/README.md)을 사용하세요.

## 포함·제외 기준

포함: 수정/미추적 소스, 문서, LaTeX/PDF, 실행 계획, 원자료, 모델 파일, 예전 제출물, 임시 연구 스크립트와 중간 산출물. 원래 바이트를 유지하며 원자료를 정리한다는 이유로 수정하지 않았습니다.

제외: `.git` 데이터 및 포인터, 설치된 가상환경, `node_modules`, 파이썬/도구 캐시, 인증정보용 파일, 이번 전달 자체의 임시 작업 폴더. 정확한 경로와 사유는 manifest의 `excluded`를 보세요. 기존 Git 이력 전체나 로컬 컴퓨터의 다른 프로젝트를 백업하는 작업은 아닙니다.

진행 중인 자동 연구 때문에 캡처 종료 뒤 생긴 파일은 이 스냅샷에 포함되지 않을 수 있습니다. 캡처 시각과 원본 Git HEAD를 manifest에 기록했습니다. 각 파일은 읽기 전후 크기·수정시각을 확인했지만 여러 파일을 동시에 고정한 원자적 스냅샷은 아닙니다.

대용량 첨부파일은 main의 Git 객체에 넣지 않고 같은 저장소의 Release에 둡니다. 따라서 **main clone만으로 원자료까지 전부 내려받아지는 것은 아닙니다**. main의 이 문서와 manifest, Release 첨부파일을 함께 보존해야 복원할 수 있습니다.
