# Standalone camera predictive prototype V1

Source SHA256: `d2bd8a0855876f5cc4d281bd1183646ad29bd27e7f9231a4af6d917e901b844e`. The offline builder preserves the exact RearClear source prefix and extracts only the separately validated public four-tire predictor, causal HUD observer, camera geometry and fixed joint-control planner. Submitted inference imports NumPy plus standard-library math, copy and time, and no simulator or project module.

Each call runs the parent perception/fallback once, then observes the current camera. It compares up to 72 constant legal controls against three representative, correlated state hypotheses; these are not a complete uncertainty set. Actual hull poses, full sampled body support, all current circles and valid inherited pass memory constrain every predicted tick. A separate asphalt field fills only known dark-car and detected-circle core pixels, preserving other unknown regions. The hull adapter derives projection velocities from actual hull chords, including rotation of the compound center offset. The stop backup begins after the first executed 0.08-second block. No old pursuit command, center-return objective or reference speed ceiling is used for feasible predictive actions.

Low speed, sensor innovation, clipped HUD/yaw, unsupported road or absence of a feasible control retain the parent's action. A three-second prediction callback deadline bounds planning; only the final emitted action advances the observer and inherited steering history. Runtime-dependent deadline fallback is possible and must be checked by cold repeats. This prototype is experimental and has no adoption or performance claim.
